# 智联招聘简历 PDF 格式参考

## 简历文本结构（pypdf 提取后的 raw text）

求职意向

## 已知的 PDF 文本提取问题

### 1. 数字和单位跨行拆分

PDF 排版导致数字和单位分散在多行：
```
原始: "1万-1.5万/月"
PDF提取: "1\n万\n-1.5\n万\n/\n月"
```

解决方案：`fix_fragments()` 中薪资正则合并。

### 2. 公司名含括号时跨行拆分

```
原始: "百威(中国)销售有限公司"
PDF提取: "百威\n(\n中国\n)\n销售有限公司"
```

解决方案：`COMPANY_PAREN_FIXES` 正则合并 + `_merge_company_lines()`。

### 3. 文本顺序与视觉顺序不一致

部分 PDF 的文本提取顺序异常：
```
视觉顺序: 工作经历 → [公司A] → [公司B] → 教育经历 → [学校]
文本提取: 工作经历 → 教育经历 → [信息头部] → [公司A] → [公司B] → [学校]
```

判断条件：`工作经历` 与 `教育经历` 之间内容过短（<200字符）。

解决方案：扩展搜索到文本末尾，并通过教育内容特征（统招/本科/大专 + 纯年份范围）识别教育段边界。

### 4. 标签行混入公司名

"工作描述" 后的技能标签（如"渠道销售"、"区域销售"、"售后服务"）可能被误认为公司名的一部分。

解决方案：`_get_bad_start()` 维护标签匹配列表，精确匹配或完整行匹配。

### 5. 岗位名与技术标签共存

同一行可能包含岗位名和非岗位文本（如 "销售总监" vs "区域销售"）。

解决方案：标签类使用 `\s*$` 精确行匹配，避免子串误杀。

## 解析策略要点

1. **公司检测**：优先匹配完整后缀（`有限公司|总公司|集团公司|...`），失败时启用 `_is_potential_company()` 启发式（要求含业务实体关键词 + 6行内有时间范围）
2. **岗位提取**：公司行与时间行之间的非标签内容，自动去除括号包裹的子岗位
3. **时间解析**：`\d{4}\.\d{1,2}\s*-\s*(至今|\d{4}\.\d{1,2})`，并向后搜索在职时长
4. **教育边界**：学校后缀 + 后续出现统招/学历关键字或纯年份范围 → `continue` 跳过该条目继续解析

### 6. 标记文字含空格（新增）

PDF 中的标记文字可能因排版含空格：
```
"工作经 历" / "求职意 向" / "教育经 历"
```

解决方案：所有标记正则改为 `\s*` 容错匹配。

### 7. 公司名后缀 `总公司`（新增）

部分公司名为 `XX有限总公司`，需将 `总公司` 加入后缀列表。

### 8. 教育经历后续不再 `break`（重要修复）

原代码在检测到教育机构后执行 `break` 退出整个工作经历解析循环，导致教育标记之后的内容（可能是实际工作经历）被完全跳过。

解决方案：改为 `continue`，仅跳过当前教育条目，继续解析后续行。

### 9. 无后缀公司名检测（新增）

部分公司名不含标准后缀（如 `恒元亿品商贸`、`中建八局土木`），需启发性检测：
- 行含中文 + 长度 3-30 + 含业务实体关键词（科技/商贸/实业/建设等）
- 不匹配排除词（查看/下载/运营管理/战略管理等）
- **必须在后续 6 行内找到时间范围**（强制）

### 10. 岗位名空格修复（新增）

PDF 排版导致岗位名内部空格：
```
"副总经 理" → "副总经理"
"总 助" → "总助"
"大 客户" → "大客户"
"咨 询服务" → "咨询服务"
```

解决方案：`fix_fragments()` 中特定词组空格合并。

### 11. 独立括号行合并（新增）

子岗位括号跨行：
```
"(\n销售团队经理\n)" → "(销售团队经理)"
```

解决方案：`fix_fragments()` 中 `\(\s*\n\s*([\u4e00-\u9fa5a-zA-Z/、]+)\s*\n\s*\)` 正则合并。

### 12. 反教育守卫（重要修复 - Round 3）

`_is_potential_company()` 对专业名称（如 `材料工程技术`）可能误判为公司，因为它含通用实体词（`工程`/`材料`/`技术`）且附近有年份范围。

解决方案：在时间范围确认后，检查后续 5 行是否含教育关键词（`统招|非统招|本科|大专|硕士|博士|学历`），或纯年份范围行，若是则判定为教育条目并拒绝。

### 13. 时间搜索窗口 off-by-one（重要修复）

`range(idx+1, min(idx+7, len))` 不包含 idx+7，导致第 7 行的时间被漏检。尤其当岗位括号跨行占用额外行时更明显。

解决方案：扩大为 `min(idx+9, len)` 并先合并独立括号行。

### 14. bad_start 误杀岗名（重要修复 - v2）

`bad_start` 模式中 `^(电话销售|门店销售|...)\s*$` 和 `^(销售)\s*$` 会错误过滤掉单行岗名（如 `电话销售`、`销售主管`），导致岗位提取为空。

解决方案：v2 将纯职位名识别移至 `_try_heuristic_company()` 中的 `pure_position_patterns` 拒绝列表，而非 `bad_start`。`bad_start` 仅用于过滤标签/描述行。

### 15. section_break 过早截断（重要修复 - v2）

当工作经历中出现 `教育经历`、`自我评价` 等标记行时，原代码执行 `break` 退出整个公司解析循环。但 PDF 文本顺序异常时，实际工作内容可能出现在这些标记之后（如吴先生的北京首创、刘先生的中建八局）。

解决方案：section 标记行改为 `continue`（仅跳过该行），不再 `break`。整个工作经历区块的终止完全由下一个公司的检测来控制。

### 16. work_raw 边界截断（重要修复 - v2）

原代码用 `工作经\s*历\s*\n(.*?)(?=\n\s*教育经\s*历|...)` 的正则先行断言截断工作经历文本。但由于 PDF 文本顺序错乱，实际工作内容常出现在 `教育经历`/`自我评价` 标记之后。

解决方案：取工作经历标记后的**全部文本** `raw[idx_w.end():]`，由逐行解析器过滤非工作内容。

## Agent 执行经验（2026-08-04 实战总结）

### 17. 多步骤任务（下载→评估）必须无缝衔接

- **现象**：下载脚本执行完成后（耗时约 2 分钟），Agent 停顿等待用户催促才继续评估流程。
- **根因**：Agent 没有将"下载+评估"视为一个原子任务，在下载脚本运行期间未预计算评估所需参数。
- **修复**：在 SKILL.md 的"执行原则"和"注意事项"中明确要求：下载脚本运行期间就预先准备好评估所需的 SKILL_DIR、Python 路径、输出路径等参数，下载返回后立即进入提取→填表→AI 评估写入流程，不得停顿。
- **经验**：长耗时脚本执行期间，Agent 应利用等待时间做准备工作，而非"忘记"后续步骤。

### 18. cmd 路径含中文空格时的调用方式

- **现象**：`cmd /c "& "path\with 中文\.venv\Scripts\python.exe" ..."` 报 `& was unexpected at this time`
- **根因**：cmd 不支持 PowerShell 的 `&` 调用运算符
- **修复**：统一使用 `cmd /c ""path\to\python.exe" "path\to\script.py" args""` 格式，外层双引号包裹整条命令，内层路径各自用双引号
